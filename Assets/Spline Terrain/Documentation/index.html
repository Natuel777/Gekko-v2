Spline Terrain Tool

A Unity editor tool that turns splines into solid terrain meshes — floor, walls and edges, updating live as you edit. Three modes, tileable per-surface materials, a curved bevel, a dense paintable floor grid (Polybrush), separable floor/wall pieces, split colliders, and baking to assets.

Requirements

Unity 6 (6000.0.62f1) URP com.unity.splines Polybrush (optional)

Everything lives under Assets/Spline Terrain/ — Runtime/, Editor/ (each with its own asmdef) and Documentation/.

Quick start

  1. Open Tools ▸ Spline Terrain ▸ Manager.
  2. In the Create tab pick a Mode and a Start shape (Circle / Square / Line), set Size / Radius, then Create new terrain.
  3. A GameObject is created with a SplineContainer, the SplineTerrain component, a child TopTransform and default materials. The mesh appears instantly.
  4. Edit the spline knots in the Scene view — the mesh regenerates live.
  5. Use WER on the terrain to move / rotate / scale the floor.

The three modes

Internal

Plateau / mesa. Fills the inside of the spline: a top floor + sloped walls down to the base outline. The floor is driven by the Top transform. Works with open splines (auto-closed).

Road

Raised path. An elevated floor of configurable width following the spline, side walls to y=0, end caps when open (a ring when closed). Top transform = height / offset / width.

External

Island with a hole. The interior becomes a hole; a ring grows outward by Outward distance + noise. Inner & outer walls; the hole rim wall is optional.

Editing — the Top transform

Each terrain has a child TopTransform; selecting the terrain shows a handle that follows the active Unity tool:

ToolEffect
W MoveFloor offset (Y = height, XZ = lateral offset).
E RotateTilts the floor; walls curve smoothly to follow.
R ScaleUniform XZ floor scale (in Road mode this is the width).

Everything is also editable numerically in the Inspector / window's Edit tab, kept in sync with the gizmo.

Key parameters

ParameterWhat it does
Resolution (segments)Points sampled along the spline (3–400). Higher = smoother & heavier.
Collider = visual shapeOn = collider identical to visual. Off = optimized collider, same shape/bevel, redundant rows collapsed.
Collider extra simplifyDecimates the perimeter for a lighter collider, at the cost of shape fidelity (0 = full).
Collider splitSplits the collider into separate pieces — see below. Never touches the visual.
Walls / SmoothingVertical subdivisions, curvature (bulge), smooth/faceted shading, and the wall–floor bevel (size / subdivisions / curvature).
UVs / TilingFloor UV scale (planar XZ) & Wall UV scale (arc-length × height). Re-tiles without touching materials.

Dense floor & separated meshes (Polybrush-ready)

Under Visual mesh layout. These change only the visual mesh and keep everything parented under the terrain GameObject.

Dense floor grid

Replaces the floor's minimal triangulation with a dense grid so it has enough polygons to vertex-paint.

Grid cell size — approximate world size of each cell; smaller = denser. Drives every mode (internally capped).

Grid style (Internal only)

Clipped Grid — regular row/column grid clipped to the outline. Even quads inside, but boundary cells split into small irregular polys.

Subdivided Contour — ear-clip + uniform triangle subdivision. Boundary follows the outline exactly (cleaner edges), interior is triangle-based.

Road & External floors are quad strips/rings — they always subdivide their quads.

Separate floor / walls meshes

Splits the visual into child GameObjects under the terrain: STT_Visual_Floor (floor material) and STT_Visual_Walls (wall + bevel). Paint the dense floor without touching the walls. Off = single combined mesh on the terrain.

Split colliders

Collider split breaks the collider into separate MeshCollider child pieces (STT_Collider…) using the submesh groups floor / wall / bevel. It never changes the visual mesh; empty groups are skipped.

All together

One collider: floor + wall + bevel.

All separate

Three colliders: floor, wall, bevel.

Floor+Bevel / Wall

Two colliders: floor+bevel together, wall on its own.

Wall+Bevel / Floor

Two colliders: wall+bevel together, floor on its own.
Live preview: the Rebuild colliders (preview) button builds the same hierarchy with temporary meshes so you can see/use the split colliders without a full bake. Colliders aren't rebuilt on every spline edit (cooking MeshColliders is expensive).

Materials & Profiles

The mesh has 3 submeshes: 0 Floor (planar XZ UVs), 1 Wall (arc-length × height), 2 Edge/Bevel. Defaults M_Floor / M_Wall / M_Edge (URP Lit).

A Profile is a ScriptableObject storing a full parameter set (and optional materials): Export new, assign a Profile, Apply profile, Save into profile. Profiles include the new floor-grid and collider-split settings.

Baking

Bake freezes the terrain into assets, organized under the terrain GameObject (the parent):

CaseOutput
Combined visual<Name>_Visual.asset on the terrain's MeshFilter.
Separated visual<Name>_Floor.asset + <Name>_Walls.asset on the STT_Visual_* children.
CollidersOne <Name>_Collider….asset per split group, on STT_Collider… children.
Data<Name>_Data.asset (all parameters + spline knot snapshot). Load from SO restores it.
Note: the optimized collider keeps the visual shape & bevel, collapses redundant vertical rows (lossless), and always uses the minimal floor triangulation — the dense paint grid is for the visual floor only.

Documentation/              READMEs (EN/ES) + this index.html

Floor caps: AddFlatCap (ear clip), AddGridCap (clipped grid via Sutherland–Hodgman), AddSubdividedCap (ear clip + uniform subdivision); Road/External use AddFloorQuadGrid. ToMeshSubset extracts submesh groups for the separated pieces & split colliders. Child pieces (STT_Visual_* / STT_Collider*) stay parented under the terrain.

Inicio rápido

  1. Abrí Tools ▸ Spline Terrain ▸ Manager.
  2. En la pestaña Create elegí un Mode y una Start shape (Circle / Square / Line), poné Size / Radius y tocá Create new terrain.
  3. Se crea un GameObject con SplineContainer, el componente SplineTerrain, un hijo TopTransform y materiales por defecto. El mesh aparece al instante.
  4. Editá los knots del spline en la escena — el mesh se regenera en vivo.
  5. Usá WER sobre el terreno para mover / rotar / escalar el piso.

Los tres modos

Internal

Meseta. Rellena el interior del spline: piso superior + paredes inclinadas hasta el contorno base. El piso lo maneja el Top transform. Funciona con splines abiertas (se cierran solas).

Road

Camino elevado. Piso elevado con ancho configurable que sigue el spline, paredes hasta y=0, tapas si es abierto (anillo si es cerrado). Top transform = altura / offset / ancho.

External

Isla con agujero. El interior queda hueco; un anillo crece hacia afuera por Outward distance + ruido. Paredes interna y externa; la pared del rim es opcional.

Edición — el Top transform

Cada terreno tiene un hijo TopTransform; al seleccionar el terreno aparece un handle que sigue la herramienta activa de Unity:

HerramientaEfecto
W MoverOffset del piso (Y = altura, XZ = offset lateral).
E RotarInclina el piso; las paredes acompañan con una curva.
R EscalarEscala XZ uniforme del piso (en Road es el ancho).

También se edita todo numéricamente en el Inspector / pestaña Edit, sincronizado con el gizmo.

Parámetros clave

ParámetroQué hace
Resolution (segments)Puntos muestreados del spline (3–400). Más = más suave y más pesado.
Collider = visual shapeActivo = collider idéntico al visual. Apagado = collider optimizado, misma forma/bevel, filas redundantes colapsadas.
Collider extra simplifyDecima el perímetro para un collider más liviano, a costa de fidelidad de forma (0 = completo).
Collider splitSepara el collider en piezas distintas — ver abajo. Nunca toca el visual.
Walls / SmoothingSubdivisiones verticales, curvatura (abombado), shading smooth/facetado y el bevel pared–piso (size / subdivisiones / curvatura).
UVs / TilingFloor UV scale (planar XZ) y Wall UV scale (longitud de arco × altura). Re-tilea sin tocar materiales.

Piso denso y meshes separados (listo para Polybrush)

Bajo Visual mesh layout. Solo cambian el mesh visual y mantienen todo parentado bajo el GameObject del terreno.

Grilla densa de piso

Reemplaza la triangulación mínima del piso por una grilla densa para que tenga suficientes polígonos para pintar por vértices.

Grid cell size — tamaño aproximado en mundo de cada celda; más chico = más denso. Maneja todos los modos (topeado internamente).

Estilo de grilla (solo Internal)

Clipped Grid — grilla regular de filas/columnas recortada al contorno. Quads parejos adentro, pero las celdas del borde se parten en polígonos chicos irregulares.

Subdivided Contour — ear-clip + subdivisión uniforme de triángulos. El borde sigue exactamente el outline (bordes más limpios), interior a base de triángulos.

Los pisos de Road y External son tiras/anillos de quads — siempre subdividen sus quads.

Separar meshes de piso / paredes

Separa el visual en GameObjects hijos bajo el terreno: STT_Visual_Floor (material de piso) y STT_Visual_Walls (pared + bevel). Pintás el piso denso sin tocar las paredes. Apagado = un único mesh combinado en el terreno.

Colliders separables

Collider split parte el collider en piezas MeshCollider hijas (STT_Collider…) usando los grupos de submeshes piso / pared / bevel. Nunca cambia el mesh visual; los grupos vacíos se omiten.

Todo junto

Un collider: piso + pared + bevel.

Todo separado

Tres colliders: piso, pared, bevel.

Piso+Bevel / Pared

Dos colliders: piso+bevel juntos, pared aparte.

Pared+Bevel / Piso

Dos colliders: pared+bevel juntos, piso aparte.
Preview en vivo: el botón Rebuild colliders (preview) arma la misma jerarquía con meshes temporales para ver/usar los colliders separados sin un bake completo. No se reconstruyen en cada edición del spline (cocinar MeshColliders es costoso).

Materiales y Perfiles

El mesh tiene 3 submeshes: 0 Floor (UVs planares XZ), 1 Wall (longitud de arco × altura), 2 Edge/Bevel. Por defecto M_Floor / M_Wall / M_Edge (URP Lit).

Un Perfil es un ScriptableObject que guarda un set completo de parámetros (y materiales opcionales): Export new, asignar Profile, Apply profile, Save into profile. Los perfiles incluyen los nuevos ajustes de grilla de piso y de separación de colliders.

Bake

El bake congela el terreno en assets, organizados bajo el GameObject del terreno (el padre):

CasoSalida
Visual combinado<Nombre>_Visual.asset en el MeshFilter del terreno.
Visual separado<Nombre>_Floor.asset + <Nombre>_Walls.asset en los hijos STT_Visual_*.
CollidersUn <Nombre>_Collider….asset por grupo, en los hijos STT_Collider….
Datos<Nombre>_Data.asset (todos los parámetros + snapshot de knots). Load from SO lo restaura.
Nota: el collider optimizado mantiene forma y bevel del visual, colapsa las filas verticales redundantes (sin pérdida) y siempre usa la triangulación mínima del piso — la grilla densa de pintura es solo para el piso visual.
